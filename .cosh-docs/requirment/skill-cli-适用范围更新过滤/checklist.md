# Skill CLI 适用范围更新过滤 Checklist

确认状态：已确认

## 验收 Checklist

### CHK-001 元数据默认通用

- 关联需求点：未声明适用范围的历史 skill 默认视为通用。
- 验证方法：准备一个不包含适用 CLI 字段的 `SKILL.md`，分别对至少两个 CLI 执行更新流程或对应单测。
- 预期结果：该 skill 在所有目标 CLI 更新中都参与同步、校验和 `managed_skills` 写入。

### CHK-002 多 CLI 适用范围

- 关联需求点：一个 skill 可以声明适用于多个 CLI。
- 验证方法：准备一个声明适用于两个 CLI 的 skill，分别以范围内 CLI 和范围外 CLI 运行更新流程。
- 预期结果：范围内 CLI 会同步该 skill；范围外 CLI 会跳过该 skill。

### CHK-003 不适用 skill 被过滤

- 关联需求点：当前 CLI 不在声明范围内时，该 skill 在更新流程中被跳过。
- 验证方法：准备通用 skill、当前 CLI 专属 skill、其他 CLI 专属 skill 混合仓库，执行当前 CLI 更新。
- 预期结果：只安装通用 skill 和当前 CLI 适用 skill；其他 CLI 专属 skill 不出现在目标 skills 目录中。

### CHK-004 汇总提示表达为预期跳过

- 关联需求点：跳过提示强调“已跳过不适用于当前 CLI 的 skill”。
- 验证方法：捕获更新命令输出。
- 预期结果：输出包含跳过数量和原因，语义为正常过滤，不包含失败或错误表达。

### CHK-005 同步数量只统计实际同步

- 关联需求点：跳过不适用 skill 不应被计入成功同步数量。
- 验证方法：在混合仓库中执行更新，并检查 `UpdateResult.synced_count` 和完成文案。
- 预期结果：同步数量等于实际安装的适用 skill 数量。

### CHK-006 校验只检查适用 skill

- 关联需求点：同步、校验、托管清理和配置写入都以过滤后的 skill 集合为准。
- 验证方法：启用文件校验，目标目录中只安装适用 skill，不安装不适用 skill。
- 预期结果：校验不会因为不适用 skill 未安装而失败。

### CHK-007 托管清理使用过滤后集合

- 关联需求点：不适用于当前 CLI 的 skill 不再由当前 CLI 更新。
- 验证方法：先让某 skill 作为当前 CLI 的 `managed_skills` 存在，再修改其元数据为仅适用于其他 CLI 后执行更新。
- 预期结果：该 skill 从当前 CLI 的 `managed_skills` 中移除；已安装副本按过期托管 skill 清理规则删除。

### CHK-008 严格校验失败不写成功状态

- 关联需求点：兼容现有严格校验失败时不写入成功状态的行为。
- 验证方法：构造严格校验失败场景，并包含适用范围过滤。
- 预期结果：失败时不写入 `last_commit`、`last_updated_at` 和新的 `managed_skills` 成功状态。

### CHK-009 元数据非法值有明确反馈

- 关联需求点：避免未知 CLI 或误拼写导致维护者误判。
- 验证方法：准备声明未知 CLI 或格式非法的 `SKILL.md`，运行标准检查或更新前检查。
- 预期结果：命令给出明确错误或警告，指出非法字段和值。

### CHK-010 显式指定不适用 skill 时仍跳过

- 关联需求点：用户显式指定更新某个不适用于当前 CLI 的独有 skill 时，也应跳过并提示原因。
- 验证方法：若更新命令存在指定单个 skill 的入口，则针对不适用 skill 执行指定更新；若当前版本无该入口，则在评审记录中标记为未来入口的约束。
- 预期结果：存在入口时跳过并提示不适用于当前 CLI；不存在入口时不阻塞本期实现。

### CHK-011 旧 skill 无需迁移

- 关联需求点：旧 skill 不做强制迁移，全部按通用处理。
- 验证方法：使用现有仓库中的未声明字段 skill 执行 `check` 和 `update`。
- 预期结果：不因缺少适用 CLI 字段报错，且行为与当前版本一致。

### CHK-012 文档说明维护者声明方式

- 关联需求点：维护者需要在 skill 自身元数据中声明适用 CLI 范围。
- 验证方法：检查 README、技能标准文档或相关开发文档。
- 预期结果：文档说明字段语义、未声明默认通用、多 CLI 声明方式和跳过行为。
