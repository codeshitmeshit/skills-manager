# Skill CLI 适用范围更新过滤需求

## 背景

当前更新流程会扫描仓库中所有合法 skill，并同步到用户指定的 CLI。随着不同 CLI 之间出现专属 skill，例如 `openclaw-skills` 只适用于 `openclaw`，其他 CLI 在执行更新时不应处理这类 skill，否则可能导致错误更新、错误安装或用户困惑。

## 目标用户

主要用户是 skill 维护者。维护者需要在 skill 自身元数据中声明该 skill 适用于哪些 CLI，从而让更新流程自动过滤不适用于当前 CLI 的 skill。

CLI 使用者是间接受益用户。他们运行更新命令时，应看到不适用 skill 被预期跳过的汇总提示，而不是把这类跳过理解为失败。

## 产品目标

- 支持 skill 声明适用 CLI 范围。
- 未声明适用范围的历史 skill 默认视为通用，所有 CLI 都可以更新。
- 当 skill 声明适用 CLI 后，只有当前 CLI 在声明范围内时才参与更新。
- 当前 CLI 不在声明范围内时，该 skill 在更新流程中被跳过，并通过汇总提示说明原因。
- 用户显式指定更新某个不适用于当前 CLI 的独有 skill 时，也应跳过并提示原因。

## 范围

本期包含：

- 在 skill 自身元数据中支持声明“适用 CLI 范围”。
- 支持一个 skill 适用于多个 CLI。
- 更新流程基于当前 `cli_name` 过滤 skill。
- 同步、校验、托管清理和配置写入都以过滤后的 skill 集合为准。
- 更新输出提供汇总提示，强调“已跳过不适用于当前 CLI 的 skill”。
- 旧 skill 无需迁移；没有声明范围时按通用处理。

## 非目标

- 不做历史 skill 的强制批量迁移。
- 不引入 CLI 分组或家族概念。
- 不隐藏仓库中的不适用 skill；只影响更新处理范围。
- 不在本期设计跨 CLI 强制更新能力。
- 不改变已有 CLI 的基本配置模型。

## 已澄清结论

- 主要用户：skill 维护者。
- 适用范围：一个 skill 可以声明适用于多个 CLI。
- 默认行为：未声明时视为通用。
- 声明位置：skill 自身元数据。
- 跳过提示：汇总提示，不逐条刷屏。
- 成功标准：减少错误更新，尤其是其他 CLI 不再更新专属 skill。

## 关键约束

- 该属性应避免命名为“独有”一类只能表达单 CLI 的概念，产品语义应是“适用 CLI 范围”。
- 默认通用必须兼容已有 skill。
- 过滤规则必须贯穿更新后续步骤，不能只影响安装。
- 跳过不应被表现为失败。
