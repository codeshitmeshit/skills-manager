# Superpowers 实时观察板

观察板用于查看和可选控制，不是唯一入口。用户完全不打开页面时，自然语言仍调用同一后端门禁推进流程。

## 启动

显式使用本 skill 开始技术方案评审、正式研发或查看进度时，在建立 `<work-id>` 基础状态后自动运行：

```bash
python3 <skill-root>/scripts/serve_superpowers_dashboard.py \
  --project <目标仓库> \
  --work <work-id> \
  --port 57171 \
  --open
```

其中 `<skill-root>` 是当前已加载 `SKILL.md` 所在目录。启动前将它解析为绝对路径，不能依赖目标仓库的当前工作目录。

服务默认只监听 `127.0.0.1`；本地正式启动必须组合使用 `--port 57171 --open`，传入 `0`、`49999` 或其他端口必须失败。端口冲突时不得降级。必须输出最终可访问 URL，并保持服务贯穿后续研发阶段。自动打开失败不阻塞研发流程，保留服务并提示用户手动打开最终 URL。

目标仓库位于 CloudDev 等远端环境时，远端命令去掉 `--open`，仍固定使用 `--host 127.0.0.1 --port 57171`。然后在用户本机建立固定一对一隧道：

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:57171:127.0.0.1:57171 \
  <remote-host>
```

隧道成功后在本机系统默认浏览器打开 `http://127.0.0.1:57171/?work=<work-id>`。不得把本机端口映射成随机端口，也不能把远端 `--open` 当成本机自动打开。若本机或远端 `57171` 已被占用，先确认是否为当前开发任务的观察板；不是则报告冲突并停止。

服务发现 `.superpowers/byted-work/` 下的多个开发任务，通过 `?work=<work-id>` 切换。用户仅解释、测试或维护本 skill 及其资源时不自动启动，避免维护过程递归打开观察板。

## 页面

导航包含总览、技术文档、评审、规格、计划、验证和最右侧强调色 Tasks。评审页展示知识模式、三路进度、未通过风险点、证据与建议修改；文档修订判断为 `carry-forward` 时显示“冻结文档 vN · 无需全量复评”，实质变化或判断无效时明确提示全量复评。P0、P1、P2、P3 分别用红、橙、黄、蓝标识。P0 显示“强制阻塞”且不提供豁免入口；未闭合 P1/P2/P3 可填写必填原因后设为不阻塞，并可恢复阻塞。Tasks 页顶部切换推进模式。

逐一任务校验时，当前任务右上角只保留“推进下一个任务”。按钮置灰时在任务卡内逐条展示原因，包括暂存区为空、尚未暂存改动、范围外文件、远程 UT 或 CR 证据不匹配。后续任务未获授权时显示 `待授权`，不能显示为当前任务；此时若工作区已有代码改动，列出全部未授权文件并把实施阶段置为阻塞。兼容旧状态时，工作区干净后显示“授权 Task N”，只补录下一任务授权而不创建代码提交。连续模式不渲染该按钮。页面不单列 artifacts 或重复展示计划文件中的任务文档。

## 实时性

服务监听原生规格、计划、SDD 进度、字节证据和 Git 状态，通过 SSE 推送版本化快照。前端断线自动重连；版本不连续时全量刷新。原子替换、短暂半写入或解析失败时保留最后有效快照，同时显示阻塞错误，不能把未知状态当成通过。

每次成功投影后，把不含读取时间的最后有效状态原子写入 `.superpowers/byted-work/<work-id>/dashboard-state.json`。该快照不参与工作流版本哈希，不是研发或门禁证据。服务重启时先按真实状态文件重新投影；投影暂时失败时才恢复该快照，并标记为过期、展示错误、禁用全部推进动作。恢复真实投影后覆盖快照并恢复实时状态。

开发任务、标签、文档和总览阶段写入 URL 查询参数；浏览器刷新、服务重启或重新打开固定 URL 后恢复当前视图。已通过阶段的空阻塞与空修复分别显示“无阻塞”和“无需修复”，不能显示成“未记录”。SSE `read-error` 只显示过期提示并保留最后有效页面，不能清空已有数据。

所有写请求包含 `work`、期望状态版本和幂等键。后端重新校验前置门禁、文档哈希、代码 SHA 和任务范围，拒绝过期或伪造请求。
