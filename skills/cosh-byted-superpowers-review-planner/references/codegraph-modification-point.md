# CodeGraph 修改点定位规范

## 原则

CodeGraph 用于发现候选代码实体、调用链和影响面，不直接替代当前 commit 的源码。固定顺序为：

`CodeGraph 发现 -> 源码复核 -> 变量流确认 -> 修改点选择 -> 用户确认 -> 创建 design`

禁止先创建 design，再用 CodeGraph 为既定方案寻找证据。

## 查询与复核

1. 已知实体时使用精确符号查询；未知时先语义检索，再按调用方、被调用方和数据结构逐步收敛。
2. 记录候选入口、实现、协议源、配置、测试和上下游，不把第一个命中直接当修改点。
3. 使用本地仓库检索和定点阅读复核索引结果，确认实体仍存在于当前 commit。
4. 沿赋值、读取、参数、返回值、字段和闭包捕获追踪变量流。
5. 索引与源码不一致时以源码为准，并标记索引可能过期。

## 修改点卡片

每个修改点至少包含：

- 仓库与基线
- 文件
- 符号
- 变量
- 类型
- 定义位置
- 当前值来源
- 相关读取行
- 相关写入行
- 预期变化
- 上下游影响
- 对应 scenario
- 测试锚点
- 排除的替代点
- 未决假设

无法精确到变量时说明原因，并至少精确到最小表达式、字段或协议定义。未决假设会改变 design 时停止并补证据。

## Design 边界

- 一个修改点对应一个明确 design 决策；多个点说明依赖顺序。
- design 必须引用卡片中的文件、符号、变量和数据流事实。
- design 需要超出已确认修改点时，退回 CodeGraph 分析和修改点确认，不得直接扩展实现范围。
