# 必要决策与自主处理规则

## 先处理，后提问

风险等级表示影响，不代表必须询问用户。先读取已有资料和可访问的代码证据，把问题分成自主修正、待补证据、用户决策，遵守 SKILL.md 的自主处理边界。

- P1/P2：在既定目标和授权内，能依据事实修正的方案缺陷，由主 Agent 修正文档、伪代码、测试设计和调用图，再交相应视角复审。P3 同样直接处理并汇总。
- P0：立即报告并阻止定稿。其他等级的阻塞项也必须解决并复核后才能放行。
- 查文件、函数、鉴权复用点、调用方向和命名是 Agent 的调查任务，不把代码问题抛回用户。
- 多种技术实现路径不自动产生用户问题；优先选择有证据、可复用、修改面最小的方案并记录依据。不得虚构现有能力或容量指标。

## 只有这些事项需要交互

先穷尽已有资料和可用只读证据，再对以下事项提问：

- 业务目标、范围或验收口径存在实质冲突。
- 需要改变权限边界、获取安全/合规批准、承诺预算或 SLA、决定不可逆迁移。
- 需要接受尚未消除的剩余风险；Agent 不能代替用户接受风险。
- 缺少无法查得的关键业务事实，例如容量预估或合法的数据使用范围。
- 外部文档写入缺少明确授权或目标；已有明确授权不重复确认。

标题、措辞、图表排版和有证据的实现细节不单独询问。等待 subagent 时整理草稿或证据，没有必要决策时等待结果，不为了保持交互而创造问题。

## 提问方式

一次提出一个当前必要决策：说明要决定什么、推荐方案和关键代价。不把全部风险逐项转成选择题，不重复询问已回答的问题。

可枚举时提供 2–3 个真实可行选项，不凑数；无法枚举时简短询问所缺事实。原生输入工具仅在当前环境支持且适用时使用，遵守工具字段限制；否则用简洁文本提问。

问题文档记录 ID、章节、待决策事项、不能自主决定的原因、建议及依据、不确认风险、用户答复和状态。

## 闭环记录

每项风险保留原始等级、证据、处理方式、自主修正内容、回填位置、复审视角与结论、剩余风险。修正后标记待复审，通过后再关闭，不通过降级或删除记录假装解决。

最终汇总已自主解决的 P1/P2 数量和主要改进，突出剩余阻塞及必要决策，不逐项请求审批。

同一问题连续两轮修正仍无有效进展时停止自动循环，说明缺失证据或必要决策。用户接受风险不代表阻塞项通过，仍遵守模板硬门禁。
