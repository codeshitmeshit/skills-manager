# OpenSpec 工作流依据

## 信息源优先级

按以下顺序确定规则，低优先级内容不得覆盖高优先级内容：

1. 当前项目安装生成的 OpenSpec skills、commands 和 schema。
2. OpenSpec 当前版本的官方文档与官方仓库。
3. 当前项目 `openspec/` 配置、自定义 schema 和已有 artifacts。
4. 本 skill 的技术评审规则。
5. 本 skill 的示例；示例仅用于说明，不是权威格式。

如果发生冲突，停止推进并说明冲突来源和采用高优先级规则的影响。

## 运行时发现

- 先检查当前项目和本地环境，不得假设某个版本专属命令必然存在。
- 优先使用当前项目实际提供的 OpenSpec skill 或 command；只有缺少对应能力时才查阅官方当前文档。
- 读取当前项目生成的 agent 指令、schema、配置和 artifact 状态后，再决定下一步操作。
- 状态查询和转换必须使用 OpenSpec 能力，不解析或维护平行的本地状态文件。
- 不在本 skill 中固化会随 OpenSpec 版本变化的命令名、参数或 artifact 模板。

## 准备 OpenSpec

1. 检查 OpenSpec 是否已安装，并识别当前可用版本和官方操作入口。
2. 未安装时，先告知用户将执行的安装动作，再按官方当前安装说明安装。
3. 项目未初始化时，先告知用户将产生的项目文件，再使用当前版本提供的初始化能力。
4. 已安装但项目 agent 指令过期时，先展示刷新影响，获得用户确认后再使用官方能力刷新。
5. 已存在 OpenSpec 配置、自定义 schema 或 artifacts 时，不得自动覆盖、重建或降级。
6. 安装、初始化、刷新、schema 读取或状态读取失败时立即停止，不得绕过 OpenSpec 编码。

## Artifact 推进

- 使用 OpenSpec 当前 schema 确定 artifact 名称、依赖和合法推进顺序。
- 每次推进前读取实际状态，确认当前 change 和可执行操作；完成后再次读取并报告状态。
- 创建或修改 artifact 时遵循当前项目生成的 skills、commands 和 schema。
- artifact 格式以项目实际 schema 为准，不从本 skill 的文字或示例反向推导格式。
- 当前状态冲突、artifact 不完整或校验失败时停止，先修复 OpenSpec 状态。

## Task 实现与状态更新

- 默认从未完成 tasks 中选择一个 task 执行，不得自行推断用户授权批量实现。
- “继续”“开始实现”“按计划执行”等普通推进语句只授权当前一个 task。
- 只有用户明确要求“一次全部实现”“批量实现”或明确给出连续执行范围时，才允许在授权范围内连续执行。
- 单个 task 的固定顺序是：读取状态、报告范围、实现、最小充分验证、展示 CR 材料、等待用户 CR、等待提交确认、commit。
- 用户 CR 通过但未明确同意提交时，仍视为未提交，不得创建 commit 或更新 task 完成状态。
- 提交成功后，使用当前项目实际提供的 OpenSpec 能力更新对应 OpenSpec task 状态，再重新读取状态验证更新结果。
- 单任务模式下，task 状态更新后必须停止并等待用户确认继续下一任务。
- 批量模式仍须保持 task 边界；每个 task 分别验证、提交并更新状态，不得把多个 task 混成无法独立 CR 的单次变更。
- 如果一个 task 无法独立验证或提交，先说明依赖关系并等待用户决定是否扩大当前 task 范围。

## 规格变化

- 实现期间出现任何需求变化时立即暂停编码。
- 先使用 OpenSpec workflow 更新需求规格并等待用户重新确认。
- 规格确认后检查 design、tasks 和验证场景的影响范围。
- 更新所有受影响 artifacts，并重新执行对应人工确认门禁。
- 受影响阶段全部重新确认后才能恢复编码；禁止先改代码再补规格。

## 验证与归档

- 使用当前版本提供的 OpenSpec 验证能力检查 artifacts、任务完成度和规格场景。
- 展示 OpenSpec 验证结果、关联测试命令、输出摘要和未覆盖项，不用无证据的完成声明代替验证。
- 用户确认测试结果后仍需等待最终归档确认。
- 只有最终确认后，才调用当前版本提供的 OpenSpec 归档能力，并在归档后重新读取状态。

## 异常与停止条件

遇到以下任一情况必须停止并向用户说明，不得回退到旧流程：

- 无法确认 OpenSpec 官方当前安装或操作方式。
- 安装、初始化或刷新失败。
- 项目配置、自定义 schema 或 artifacts 存在冲突或损坏。
- OpenSpec 状态与实际 artifacts 不一致。
- 所需人工确认尚未完成。
- 实现或测试结果与已确认规格不一致。
