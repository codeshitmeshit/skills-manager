# 技术方案 Review Rubric

使用本 rubric 评审技术方案、复杂需求或需求文档中的技术实现计划。目标不是复述方案，而是发现阻塞风险、澄清缺失信息，并把可验证事项沉淀为 checklist。

## 输入整理

先从需求或方案中提取这些事实，缺失时标记为待澄清：

- 背景问题：当前痛点、触发场景、影响对象、现有机制为什么不足。
- 目标：业务目标、技术目标、非目标、成功指标或验收口径。
- 方案路径：主链路、异步链路、补偿链路、后台任务、配置开关、降级路径。
- 影响面：接口、存储、缓存、消息、配置、权限、用户体验、上下游依赖。
- 约束：QPS、容量、延迟、数据量、灰度范围、兼容性、上线窗口。

## Review 输出结构

`review.md` 必须包含：

1. `评审结论`：通过、带条件通过、需补充后再评审三选一。
2. `阻塞问题`：只列会影响设计成立、上线安全或验收判断的问题；每项给出建议选项。
3. `主要风险`：按稳定性、数据一致性、安全、性能、兼容性、可回滚性、可观测性分类。
4. `关键追问`：用 Q&A 方式覆盖设计决策，追问方案为什么这样做、替代方案是什么、代价是什么。
5. `测试与上线建议`：列出必须进入 checklist 的验证点、灰度步骤和回滚门禁。

## 核心评审维度

### 1. 问题与目标

- 问题是否有清晰触发场景，而不是抽象描述。
- 用户影响、业务影响、监控影响是否具体。
- 目标是否能反推验收标准；是否明确不解决什么。
- 成功指标是否可观测、可回归。

### 2. 主链路影响

- 主链路是否只增加低成本操作；高 QPS 链路是否避免扫描、同步等待和外部强依赖。
- 异步触发是否非阻塞、有界、可丢弃或可补偿。
- 当前请求语义是否保持稳定；是否改变对外协议或错误语义。
- 降级时是否优先保护主链路。

### 3. 数据一致性与幂等

- 新增写操作是否幂等；重复执行是否安全。
- 是否识别并解释并发竞态，例如后台任务与在线刷新、重试与删除、读修正与写入并发。
- 是否明确过期阈值、锁 TTL、去重粒度、数据恢复机制。
- 误删、漏删、重复清理等异常结果是否可恢复。

### 4. 容量与性能

- 是否给出关键流量级别、单 key 或单对象数据量、worker 并发、队列容量。
- 是否有防堆积设计：限流、去重锁、有界队列、丢弃策略、worker 数控制。
- 配置热更新与非热更新项是否区分清楚。
- 是否说明容量异常时应降低灰度、关闭开关还是扩容。

### 5. 稳定性与回滚

- 是否有总开关、灰度比例、并发数量、队列容量、阈值等可控参数。
- 关闭开关后哪些行为停止，哪些历史任务或残留状态仍可能继续影响线上。
- Redis、RPC、MQ、配置中心等依赖失败时是否遵循“宁可不做，也不做错”。
- 回滚是否只需配置变更，还是需要代码回滚、数据修复或重启。

### 6. 安全与权限

- 是否新增外部入口、权限路径、跨租户风险或敏感数据处理。
- 外部请求是否能诱导系统执行高风险清理、写入或资源消耗。
- 审计信息是否足够支撑问题排查。

### 7. 可观测性

- 是否覆盖调度、入队、队列满、消费成功/失败、删除量、耗时、配置变更、回滚开关等指标。
- 高频失败是否避免日志风暴。
- 是否能通过指标判断：是否触发、是否消费、是否生效、是否异常放大。

### 8. 测试与上线

- checklist 必须覆盖正常流程、边界条件、异常依赖、配置热更新、回滚、容量和观测指标。
- 灰度方案必须从“代码上线 + 开关关闭”开始，逐步放量，并定义观察指标。
- 每一步都要有独立回滚方式和继续放量门槛。

## 评审问题模板

优先用这些问题逼近风险：

- 这个方案最容易拖垮主链路的点在哪里？如何证明不会发生？
- 哪些操作从 O(1) 变成了 O(N)？N 的上界是什么？
- 如果异步任务丢失、重复、延迟或堆积，业务结果是否仍可接受？
- 如果清理、修正或补偿逻辑误判，多久能自动恢复？用户会感知什么？
- 哪些配置热更新，哪些必须重启？错误配置如何处理？
- 关闭总开关后，是否真的停止所有新行为？
- 对外协议、返回语义、存储结构、权限范围是否发生变化？
- 监控能否区分“没触发”“触发了但没消费”“消费失败”“消费成功但无效果”？

## checklist 转换规则

从 review 进入 checklist 时，将每个风险转换为可验证项：

- 主流程风险 -> 核心业务流程测试。
- 异步与并发风险 -> 重复触发、队列满、worker 并发、幂等测试。
- 依赖失败风险 -> Redis/RPC/配置读取失败、部分失败、超时测试。
- 安全风险 -> 权限、攻击入口、跨租户、敏感数据验证。
- 可观测性风险 -> 指标、日志、告警、配置变更记录验证。
- 上线风险 -> 开关关闭上线、小流量灰度、放量门槛、回滚演练。
