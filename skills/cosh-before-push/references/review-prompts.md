# 四路代码评审 Prompts

## 最小上下文

每路只提供：`REVIEW_BUNDLE_PATH`、`BASE_REF`、`DIFF_BASE`、`HEAD_SHA`、`REMOTE_SHA`、`COMMIT_RANGE`、是否为历史覆盖，以及本路线 prompt。评审材料目录包含已提交文件快照、commit 列表、变更文件和 diff；历史覆盖时额外包含远端独有 commits 与覆盖净 diff。

所有路线追加：

> 只读评审隔离材料。禁止访问原仓库、修改文件、创建提交、切换分支或 push。除 Coco runner 可向公司内网 Coco 发送最小必要评审材料外，禁止向 AIME、互联网服务或其他未授权目标发送代码。只报告能由材料证明的问题。每项包含严重程度、文件与行号、证据、影响和修复方向；将未证实疑点和风格偏好单列。无问题时说明检查范围。

## Coco runner

在 `REVIEW_BUNDLE_PATH` 中按 `cosh-coco` 安全规则调用公司内网 Coco。允许向 Coco 发送最小必要评审材料；只发送 `Coco reviewer` prompt、通用只读约束和隔离目录内材料说明，不要发送整个 before-push skill、完整 reference 或其他路线内容。Coco 不存在或结果无效时，不调用其他外部服务，由你使用 `Coco fallback` prompt 完成评审。最终说明实际使用 Coco 还是 fallback。

## Coco reviewer

作为独立综合评审者，检查待推送行为的实现合理性、控制流、边界与失败处理、兼容性、安全与数据风险。历史覆盖场景还要检查将删除的远端 commits 和覆盖净变化。优先报告会造成错误行为、数据损坏、权限绕过、信息泄漏或维护误导的问题。

## Coco fallback

以资深维护者视角综合检查正确性、回归、安全边界、敏感数据、测试有效性，以及注释或文档与实现偏差；为每个问题给出具体触发场景。

## Correctness reviewer

沿变更调用链检查前置条件、返回值、状态转换、边界值、异常路径、兼容性和测试断言。只报告本次 push 新增或历史覆盖造成的、具有充分证据的错误行为。

## Security reviewer

检查输入验证、权限与信任边界、敏感信息、注入、路径操作、竞态、资源耗尽、失败关闭和日志暴露。历史覆盖时重点检查是否删除安全修复、配置保护或数据迁移。只报告具有具体可达路径的问题。

## Consistency reviewer

逐项核对注释、文档字符串、README/配置说明、变量与函数命名、错误消息和用户提示是否与真实实现一致。历史覆盖时核对被删除说明与最终行为。只报告会误导调用者、用户或维护者的明确不一致。

## 主执行者核验

1. 在原仓库的已评审 SHA 和必要上下文中确认位置与可达路径。
2. 判断问题是否由本次 push 新增，或由历史覆盖造成。
3. 合并根因相同的问题并注明发现路线。
4. 将成立的正确性、安全、数据和明确一致性问题列为阻断。
5. 将风格、可选重构和无失败场景推测列为非阻断建议或删除。
6. 不使用多数票；任一路发现且经核验成立的阻断问题都足以阻止 push。
