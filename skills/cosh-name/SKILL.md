# 对话标题

根据当前对话中可见的内容，生成一个能帮助用户日后辨认和检索任务的标题。

## 手动调用与 mode 参数

仅响应用户显式选择本技能或使用 `$cosh-name` 的调用。普通对话提到标题时不要自动执行本技能。

`mode` 表示标题分类前缀，不表示执行动作。支持 `mode=code`、`mode=1`，也支持调用后直接写名称或数字，如 `$cosh-name debug`、`$cosh-name 3`。

| mode 名称 | 数字编号 | 固定前缀 |
| --- | --- | --- |
| code | 1 | 【需求】 |
| dev | 2 | 【调研】 |
| debug | 3 | 【排查】 |
| custom | 4 | 【自定义】 |
| other | 5 | 【其他】 |
| explain | 6 | 【阐释】 |

- 将名称转为小写并去除首尾空白后匹配；名称与对应数字完全等价。
- 未传 `mode`、`mode=`、空字符串或只有空白时，先根据对话拟定一个推荐的完整标题（包含推荐分类前缀），再发起一轮交互，等待用户选择后更新标题。收到有效选择前不调用改名工具，也不自行采用推荐项。
- 优先使用宿主提供的交互提问工具，在问题中展示“推荐标题： 【分类】标题正文”，并提供“采用推荐”及六个前缀选项：`1 code【需求】`、`2 dev【调研】`、`3 debug【排查】`、`4 custom【自定义】`、`5 other【其他】`、`6 explain【阐释】`。工具不可用或无法展示全部选项时，用简短文字展示推荐标题和分类映射，请用户回复“采用推荐”、名称、编号或修改后的标题。预选推荐项不等于用户已确认。
- 该问题是补充缺失参数，不是额外的改名审批。用户在下一条消息回复“采用推荐”、明确接受推荐的表达、名称、数字或选中的完整选项，即视为完成本次手动调用的参数补充，无需再次调用技能。保留此前的语言、长度及“仅推荐”等限制；收到有效选择后直接执行，不再询问是否确认。
- 没有回复时保持等待，不因超时或预选项而改名。用户取消则结束；回复无效或含糊时仅请其纠正选择。
- 提供有效 `mode` 时，生成标题正文，在开头添加表中的固定前缀并更新当前任务。格式为 `【分类】标题正文`，前缀与正文之间不加空格。
- 空参时允许推荐一个分类，但只有用户明确采用推荐后才能将其用于改名；这与不得自行执行默认 mode 的规则一致。
- 用户采用推荐时，原样应用刚才展示的完整标题，不重新生成不同措辞。用户选择其他前缀时保留推荐正文，仅替换分类前缀；用户给出修改后的标题正文时保留已选前缀（尚未选择时使用已展示的推荐前缀），用户明确指定合法分类前缀时尊重该选择。不要把回复“采用推荐”或数字编号作为标题正文。
- 如果之前因“仅推荐”而未改名，用户随后明确说“采用推荐并改名”“就用这个标题”等，视为授权应用该推荐标题，无需重新调用技能；若推荐有多个且指代不清，只澄清具体采用哪一个。用户仍明确要求不改名时继续只给建议。
- `custom` 固定映射为 `【自定义】`，不需要再输入自定义前缀。不要未经用户选择或接受推荐就执行 mode，也不要让旧的 `prefix` 参数覆盖映射。
- 无效 mode（包括旧的 `rename`、`suggest`）或多个冲突的 mode 时，简短展示合法名称与编号，请用户修正，不执行改名。
- 用户明确要求仅推荐或不要改名时，尊重该限制：有效 mode 仍决定建议标题的前缀，但不调用改名工具。
- 可选参数：`language=zh|en` 指定语言，`max_length=20` 指定最大字符数（包括前缀）。不提供时遵循下方标题规则。无法满足用户指定的限制时先请用户修正，不执行改名。
- 参数由模型按此约定读取，不是 CLI 参数解析器。不要将参数内容当作 shell 命令执行。

示例：

- `$cosh-name mode=code` 与 `$cosh-name 1`：生成并更新为 `【需求】…`。
- `$cosh-name mode=debug` 与 `$cosh-name 3`：生成并更新为 `【排查】…`。
- `$cosh-name` 或 `$cosh-name mode=`：先展示推荐完整标题并询问选择；用户回复“采用推荐”则原样更新，回复 `3` 则将推荐正文加上 `【排查】` 后更新，无需再次确认。

## 拟定标题

- 提取用户的核心目标、主要对象与必要的区分信息。结合最新有效需求判断主题；不要把末尾的“帮我改标题”当成主题，也不要被中途的状态询问带偏。
- 沿用用户主要使用的语言与明确指定的命名格式。中文一般控制在 8–24 字，英文一般 4–10 个词；清晰度优先于硬性字数。
- 优先使用具体的“动作 + 对象 + 关键限定”，例如“创建对话标题插件”“排查支付回调超时”。避免“讨论”“一些问题”等空泛标题，避免没有证据的“已完成”“已修复”。
- 保留有助于区分的项目名或技术术语，但不要把密钥、个人联系方式或对话中的敏感细节写入侧边栏标题。
- 历史不完整时只依据可见内容，不臆测先前目标。若完全没有可识别的主题，简短询问主题。

## 应用标题

- 按上述参数规则判断是否只推荐；只推荐时回复“建议标题：**标题**”。
- 有效 mode 且未要求仅推荐时，直接更新标题，不增加确认步骤。根据对话主题重新生成正文，只添加一次选定前缀，不叠加旧的分类前缀。
- 优先使用宿主的 `mcp__codex_app__set_thread_title`（或工具发现中名为 `set_thread_title` 的对应工具），传入 `title`，省略 `threadId`，以当前任务为目标。若工具尚未加载，通过可用工具发现机制按名称查找。
- 不需要列出或读取其他任务，不修改其他任务，不访问网页，不修改本地会话数据库。
- 只有重命名工具成功返回后才回复“已将当前对话标题改为：**标题**”。工具不可用或失败时，输出“建议标题：**标题**”，并简短说明未能自动更新。
- 此技能在被调用时执行一次，不创建后台自动化，也不承诺持续自动改名。
