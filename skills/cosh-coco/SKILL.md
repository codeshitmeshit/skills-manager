# Coco 任务

## 目标

通过本机 `coco` CLI 在当前工作目录实际完成用户交给 Coco 的任务，并返回执行结果。不要把 Coco 和 `bytedcli aime` 混为一体，也不要只提供命令教程。

## 工作流

1. 运行 `command -v coco` 确认 CLI 可用；不可用时报告错误，不得回退到 AIME。
2. 保留用户的任务目标、约束和明确指定的文件。任务引用当前环境中 Coco 无法直接读取的内容时，先通过适用能力取得内容，再将必要上下文交给 Coco。
3. 在当前工作目录执行 `coco -p "<任务>"`，等待进程完成。除非用户明确指定，不切换目录、不创建 worktree，也不恢复其他会话。
4. 返回 Coco 的结论、文件改动和验证结果；输出过长时提炼重点，但不得隐瞒失败信息。

## 权限与失败处理

- 默认允许 Coco 在当前工作目录正常读取和修改文件。
- 不得添加 `-y`，也不得把权限模式改成 `bypass_permissions`。
- Coco 请求额外权限或因权限停止时，向用户说明具体请求，等待用户决定是否授权后再重试。
- 超时或异常退出时，保留退出状态和关键错误；不要自动把同一任务提交给 AIME。
- 用户明确要求使用 AIME 时，改用 `cosh-aime`；仅仅看到 Coco 的模型或插件名称包含 AIME，不构成切换理由。

## 质量检查

- 实际调用的是 `coco`，不是 `bytedcli aime`。
- 命令运行目录与当前工作目录一致。
- 未自行启用 `-y` 或其他绕过权限的配置。
- 最终回复区分 Coco 已完成、部分完成、权限受阻和执行失败。
